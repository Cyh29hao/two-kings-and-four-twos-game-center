# 娱乐中心 · 好友游戏室

朋友之间玩的经典三人斗地主、四人麻将与 4–10 人无限注德州扑克。独立账号、私人房间号、服务端判定出牌、娱乐积分和管理员后台。

## 使用

1. 管理员通过专属首次设置链接为 MartinHamburger 设置密码。链接中的随机密钥只用于首次设置；成功后即不能重复使用。
2. 朋友在首页注册独立用户名和密码。用户名不区分大小写，昵称可用中文。
3. 创建房间，将邀请链接或 6 位房间号发送给朋友。选定人数坐满并全部准备后自动发牌；房主可在首局前添加或移除人机。
4. 叫分、个人加倍、出牌、结算、再来一局都在牌桌完成。刷新后在大厅返回原房间。
5. `/admin` 管理房间、停用/恢复账号、设置新房间时限、修改公告、暂停开桌、查看对局与管理记录。

具体牌型、带牌约定及计分在站点的「玩法规则」中列明。仅娱乐积分，无现金、充值、提现功能。

## 运行与维护

- Vinext + React，Cloudflare Workers 运行，D1 存储。
- `npm run dev`：本地预览；`npm run build`：构建；`npm test`：规则与整局验证。
- `.env.example` 列出环境变量。`ADMIN_SETUP_HASH` 是专属设置密钥的 SHA-256，原始密钥只保存在交付给所有者的设置入口中。不要提交 `.env`。
- 管理员忘记密码时，由站点所有者签发新的 32 字节随机密钥，设置 `ADMIN_RESET_HASH`（密钥的 SHA-256）、`ADMIN_RESET_EXPIRES`（有效期截止的毫秒时间戳）、`ADMIN_RESET_USER_ID`（现有管理员的准确账号 ID），部署后交付 `/reset#key=密钥`。建议 24 小时有效；使用后同一密钥不可重复使用。只保存密钥散列，不设定用户的新密码。重设与注销全部旧会话在同一事务中完成，不影响账号、积分与记录。
- 数据模型在 `db/schema.ts`；生成迁移用 `npm run db:generate`。部署过的迁移保持不变，新修改追加迁移。
- 本地应用迁移：`node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_handy_speed.sql`。只用于尚未迁移的本地数据库。
- `tests/api.test.ts` 使用本地测试账号验证完整三人对局、并发重复提交、越权、CSRF、封禁、维护和关闭房间。仅运行于本地测试库，不在正式站点运行。

## 麻将试玩框架

- `/mahjong` 沿用现有账号、邀请链接和房间管理。136 张无花牌，四人准备后开局。
- 已确认规则：不换三张、不定缺，可吃碰杠，一人胡牌结束。胡牌优先于碰杠，碰杠优先于吃；多人可胡按距出牌者最近的座次结算。补杠可被抢胡。
- 基础胡牌为四组牌加一对将；自摸其他三家各付 1 分，点炮或抢杠由出牌者付 1 分，流局零分，杠不单独计分。特殊牌型与番数暂未启用。
- `lib/mahjong/rules.ts` 定义版本化规则预设，创建房间时保存快照；后续调整应新增版本，保留旧房间规则。`engine.ts` 负责纯规则计算；`app/api/mahjong/route.ts` 负责认证与房间操作；`lib/rooms.ts` 共用条件更新与结算事务。
- 房间状态以 `kind` 区分游戏，兼容已有无 kind 的斗地主数据，无需修改旧数据库迁移。每个账号同时仅在一个游戏房间。旧规则房间维持原积分口径。新麻将与德州使用独立筹码，斗地主含人机时不计账号积分；所有游戏记录集中在 `/history`，大厅只保留入口。
- `npm test` 覆盖两种游戏规则；麻将另有 200 局随机完整对局、牌数守恒、响应优先级和抢杠测试。`tests/mahjong-api.test.ts` 仅在本地测试库验证多人联机与后台集成。

## 同步与权限

- 客户端每 1.5 秒读取房间状态；服务端持有完整手牌，只向本人返回未出的手牌，斗地主和麻将结束后公开余牌。德州仅摊牌时公开未弃牌者底牌，弃牌者保持隐藏。
- 所有对局操作通过房间版本号进行条件更新。结算、积分与记录在同一 D1 批处理中提交，避免重复计分。
- 超时在下一次成员请求时执行；仍有玩家在线时自动推进，所有人离线后恢复访问时继续。不是后台常驻的计时进程。
- 密码使用带随机盐的 scrypt（N=16384,r=8,p=5）散列；会话随机密钥的 SHA-256 保存在数据库，浏览器使用 HttpOnly、SameSite Cookie，HTTPS 下启用 Secure。
- 账号与管理权限均在服务器检查。认证限流、同源写入验证、参数化查询已启用。
- 后台列表有明确上限：200 个账号、100 个房间、100 局记录、30 次管理操作，适合小规模朋友游戏室。
- 普通玩家尚无密码找回；管理员可通过所有者签发的一次性链接重设。已支持房间聊天、头像气泡与人机补位；尚无观战、自动匹配或大规模负载验证。

## 本轮规则版本与德州扑克

- 新斗地主房间保存 `landlord-v2` 规则快照，可开关个人加倍、炸弹/王炸加倍、春天/反春天加倍，默认全部开启。个人加倍阶段并行选择，超时不加倍。各农民与地主逐笔结算，双方均加倍时该笔乘 4；桌内实时展示累计输赢与账号积分。缺少规则快照的旧房间保持原流程。
- 新 ham 房间保存 `ham-v5`：继承 ham-v4 的无门前清/无赖子加倍、禁止弃赖、四赖胡、自摸乘 2 与手动逐张翻奖，新增严格胡法禁用列表、吃牌/抢补杠开关。禁用检查先于番型排除，不允许用九莲等拆法绕过清一色禁令；七对禁令含全部豪华等级。旧 ham-v1 至 v4 快照仍可读取与运行。
- `/holdem` 为 `holdem-v1`，默认 6 座，建房可选 4–10 座；初始 1000、每人前注 10、小盲 20、大盲 30，时限沿用后台默认，可选 15/30/45/60 秒。固定盲注、无抽水、无限注、本桌娱乐筹码。
- 德州 `lib/holdem/evaluate.ts` 枚举最佳五张，`engine.ts` 负责行动、加注权、边池和精确整数结算，`bot.ts` 仅以当前玩家可见状态做抽样胜率估计。机器人不读取牌堆或对手底牌。
- 筹码均以十进制字符串存储，结算用 BigInt。短额全下不独立重开加注权，多次短加注累计达到完整幅度时重开；同牌平分，零头按庄位后顺时针分配。无跟注的剩余下注退回。
- 德州首局后固定玩家；输光时可在局间补入一个初始筹码，记录累计带入。整桌净输赢是结余减累计带入。房主只可在局间结束，管理员中止当前手时原子退回该手全部投入；每手结果沿用 records 表，不新增数据库表。
- 德州使用当前访问者轮询推进超时及全下后的分街发牌；所有人离线时暂停推进，重连恢复。
- `tests/holdem.test.ts` 检查全部 2,598,960 个五张组合的牌型分布、边池、加注权、52 张守恒和 4–10 人随机整局；`tests/room-rules.test.ts` 验证加倍与严格禁用。`tests/holdem-api.test.ts`、`tests/room-rules-api.test.ts` 只连接本机测试服务，验证多人权限、隐私、并发下注/补筹码、退款与房间设置。它们需要本地 SQLite 夹具，不能对线上运行。

德州通行规则参考：[PokerStars Texas Hold’em](https://www.pokerstars.com/poker/games/texas-holdem/)。

## 统一游戏室与历史记录

- 三个游戏通过同一顶栏无刷新切换。根布局共享登录状态、公告与当前房间；各游戏的规则引擎和操作接口仍独立，避免跨游戏耦合。
- `GET /api/lobby` 只读取公共大厅资料；`GET /api/history` 按游戏、单局/整桌、页码查询本人记录，详情按记录 ID 懒加载。旧大厅接口继续兼容原客户端，不改写历史记录或数据库结构。
- 页面切换保留房间、手牌预选与建房草稿。缓存只在当前浏览器页面内存中保存，退出或切换账号立即清空，旧请求不能写入新账号状态。返回牌桌时立即同步最新服务器状态。
- `tests/club.test.ts` 验证导航缓存、跨账号隔离、内部房间路由和记录摘要；`tests/club-api.test.ts` 使用本地测试账号和数据库验证分页、三游戏筛选、旧记录兼容与参与者权限。
