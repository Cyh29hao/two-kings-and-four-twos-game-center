# 规则与兼容：新规则只进新房间

房间创建时保存规则快照。之后修改默认值，不会改正在玩的房间或过去的战报。不要改旧版本的含义，让旧引擎误解新状态。

## 当前默认值

| 游戏 | 当前版本 / 入口 | 重点 |
|---|---|---|
| 斗地主 | `landlord-v2`，`lib/game/engine.ts` | 三人；叫分后每人可加倍一次。地主和各农民逐笔计算，双方都加倍时该笔 ×4。建房可关闭个人加倍、炸弹加倍或春天加倍。 |
| 基础麻将 | `lib/mahjong/rules.ts` 的 BASIC | 四人 136 张，无花牌；吃碰杠；一人胡结束；新房间使用本桌筹码。旧积分房不追溯换算。 |
| ham 麻将 | `ham-v6`，`lib/mahjong/rules.ts` | 自摸通常 ×2；点炮本身 ×1。双赖子满足专门条件时，自摸与点炮的起点均为 ×4，再乘其他牌型。无门前清和无赖子加倍。 |
| 德州扑克 | `holdem-v1`，`lib/holdem/engine.ts` | 4–10 座，默认初始 1000、前注 10、小盲 20、大盲 30；无限注；允许局间补入并记录累计带入。 |

ham 的双赖子仍要求胡前恰好两张赖子，与进牌组成同一副中张顺子，进牌代表 4–8。它不是“任意持有两张赖子就 ×4”。四赖直接胡是另一条规则，不共用双赖子排除自摸的逻辑。`ham-v5` 等老快照继续按原计算方式运行。

ham 普通胡中张限制、特殊牌型、严格禁用、奖牌和杠分的完整解释由 `lib/mahjong/rule-guide.ts`、`rules.ts`、`solver.ts` 和“本桌规则”共同维护。更改牌型时同步说明和测试，不能只改表格文字。

## 计分与隐私

- 斗地主带人机的对局不改变账号积分。新麻将和德州使用独立本桌筹码。
- 筹码存十进制字符串，计算用 `BigInt`，不要转为 `Number` 后相乘。
- ham 胡牌先确认方案，再由胡牌者逐张翻两张奖牌；公开接口不能提前返回奖牌。
- 斗地主、麻将结束后显示各人的剩余手牌；德州弃牌者底牌保持隐藏。
- 公开战报使用过滤后的只读快照，不能直接公开房间 JSON。

## 如何修改规则

1. 找到现有规则预设和快照读取位置。
2. 新增版本或明确兼容字段，保留旧版本分支。
3. 写新规则正反例，同时保留旧快照测试；涉及钱数时核验收支总和与重复提交。
4. 同步建房设置、“本桌规则”和战报说明。
5. 完成 [验收](testing.md) 后再提 PR。

若要回退发布，目标版本仍必须认识线上已经存在的新房间结构。数据库迁移只追加，不删除已经运行过的迁移。不能直接把支持新规则的服务回退到完全不认识该规则的引擎。
