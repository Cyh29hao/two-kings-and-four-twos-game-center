# 素材与缓存：加内容时不用重新修三款游戏

所有表情和牌型特效共用一套登记、校验、下载、缓存和播放流程。当前在发的表情与特效约 13 MiB；数量和大小由代码计算，页面没有写死“21 个表情”或“63 个文件”。

## 新增表情只做这几步

1. 把封面和帧图集放到 `public/emotes/<包名>/<表情名>/`。使用透明 WebP，记录来源和制作说明。不要引用外站图片。
2. 在 `lib/emotes.ts` 引入你的表情包。现有包示例是 `lib/motion/emote-pack.ts`。每项填写新 `id`、名称、封面、`frames`、`enabled` 和 `sendable`。
3. 帧定义包括图集行列数、单格尺寸和每帧停留时间。不要把换一张表情图误写成旧编号，也不要省略真实帧动作。
4. 运行 `npm run assets:build`，提交生成的 `lib/motion/asset-manifest.ts`。缺文件、重复编号、越界帧或过大图集会报错。
5. 运行 `npm run check`，在 `/emotes` 逐个重播，再到实际牌桌检查气泡位置。

新增牌型特效在 `lib/motion/effects.ts` 登记，素材放 `public/effects/`。真正新增一种牌局事件时，还需要在引擎成功动作处产生公开事件、更新 `events.ts` 和触发测试；不能从聊天或昵称推测牌型。

**新增正常素材不需要修改缓存代码、三个游戏页面或手写下载清单。** `catalog.ts` 自动收集封面、备用封面和全部图集，构建时计算实际内容指纹，浏览器使用同一目录。

## 换图和下架

- 修改同一路径的图片后重新生成清单。新内容获得新指纹，只下载变更图片。
- 表情编号保存在历史聊天里。下架用 `sendable: false`，保留旧编号与素材；历史还能看，新面板不再发。
- 真正移除的缓存和旧指纹会清理。新写入的条目保留七天闲置宽限，照顾还开着旧页面的玩家；空间不足时可提前淘汰。
- 不要因为改名把旧消息映射成另一个人物或动作。

## 性能上限在哪里改

统一配置在 `lib/motion/cache-policy.ts`：

| 配置 | 当前值 | 为什么 |
|---|---|---|
| 单份压缩图片 | 4 MiB | 太大的图集先拆分，避免一次下载阻塞太久 |
| 单张图集像素 | 最多 4096 × 4096 等量像素 | 防止压缩图不大，解码后却占用大量内存 |
| 每次打开页面的自动预取 | 32 MiB | 当前包可全部自动缓存，未来扩大后仍不无限后台下载 |
| 本框架图片缓存 | 128 MiB | 达到上限按最近使用情况腾出空间 |
| 空闲已解码图集 | 32 MiB | 磁盘可存整包，但不把整包全部展开到内存 |
| 单次下载超时 | 12 秒 | 慢网失败可重试，不挂住游戏 |

浏览器会先备好封面，再单份下载图集。页面隐藏时暂停新下载，省流量或 2G 时不自动下载。玩家可点“缓存全部动画”补齐；如果未来包超过容量，界面会显示实际缓存数量，其余仍能按需播放，不谎称全部完成。

配额不足时停止本页的后台写入，避免不停下载又保存失败；主动重试可以恢复。不同页签支持时通过浏览器锁串行写缓存，同一页的重复请求始终共用下载。浏览器自己清理缓存后，下次会重新补齐。

## 出问题先查这一层

| 问题 | 查看位置 |
|---|---|
| 新素材不在面板或清单里 | `lib/emotes.ts`、`catalog.ts` 的启用与可发送状态 |
| 缓存一直未完成 | 图鉴提示、文件路径、大小、返回类型、浏览器存储空间 |
| 换图后没有更新 | 是否重新运行并提交 `assets:build` 的结果 |
| 下载不慢但播放卡 | 图集像素尺寸、帧时长、`decoded-sheets.ts`、`motion-playback.tsx` |
| 刷新又播放旧表情 | 消息/事件新鲜度与去重逻辑，不能靠缓存层解决 |

存储层只接受清单中的本站 WebP，下载不带账号凭据，保存的响应只含图片和缓存元数据。没有 Service Worker，不缓存登录、聊天、房间状态、奖牌或手牌。动画读取失败降级为封面；游戏操作继续使用原接口。

框架测试位于 `tests/motion-cache.test.ts` 和 `tests/unit/motion-framework.test.ts`。它们构造不断增大的素材集合，而不是只核对当前包的固定数量。

浏览器能力依据：[Cache API](https://developer.mozilla.org/en-US/docs/Web/API/Cache)、[图片异步解码](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/decode)。
