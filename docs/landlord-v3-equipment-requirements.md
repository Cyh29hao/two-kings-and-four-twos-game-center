# Landlord V3 装备要求

> 状态：设计约束。这里定义装备的共同语言和强度标准；具体候选放在[待定装备列表](landlord-v3-equipment-pending.md)，只有明确冻结的装备才进入[选定装备列表](landlord-v3-equipment-selected.md)。

## 1. 目标

装备是 `landlord-v3` 局前商店中的长期资产。它们应让玩家围绕「更快出完牌」或「拿到更多金币」做有趣且可辨识的选择，而不是把胜负压缩成一组隐形数值加成。

装备分为两类：

| 类别 | 核心目标 | 可以影响的环节 | 不应替代的能力 |
| --- | --- | --- | --- |
| 战力类 | 帮助持有者在本局出掉更多牌，或创造更好的出牌窗口 | 发牌后、出牌时、出牌后、炸弹、手牌管理 | 不能自动替玩家做出牌决定，不能绕过合法牌型和压制规则 |
| 经济类 | 帮助持有者获得、保留或更有效地使用金币 | 商店、购买、出售、叫/抢地主、局后收入 | 不能直接改写账户余额；所有变动必须是服务端可审计的本桌金币 |

数值流和机制流是两条设计路线，不是类别：

| 路线 | 特征 | 适合等级 | 风险控制 |
| --- | --- | --- | --- |
| 数值流 | 效果直白、结算确定、和其他装备交互较少 | 一级、二级可多一些 | 单件的牌差、金币差必须受等级上限约束 |
| 机制流 | 单看数值不大，但会改变拿牌、出牌或投资的时机，能形成组合 | 二级以上，三级为主 | 必须写明触发窗口、次数、公开性与冲突顺序 |

一件装备可以同时是数值流和机制流。例如开局弃置类装备既直接减少手牌，也会在竞价前改变持有者的手牌结构。

## 2. 等级、价格与强度

| 等级 | 固定价格 | 设计定位 | 单件应带来的感受 |
| --- | ---: | --- | --- |
| 一级 | 1 金币 | 低成本、有限帮助 | 一次小修正、一个轻量经济选择，通常不足以单独改变一局 |
| 二级 | 2 金币 | 开始影响战局 | 能稳定改善一次关键决策，或给出可感知的经济路线 |
| 三级 | 4 金币 | 体系核心或强力独立件 | 值得围绕其调整购买、竞价或出牌次序，能够形成组合 |
| 四级 | 8 金币 | 巨大变量 | 可以大幅改写局势或提供独特机制；必须有明确条件、次数或对手可见的反制窗口 |

以下不是硬编码数值，而是候选评审时的平衡尺：

| 等级 | 战力参考上限 | 经济参考上限 | 禁止的默认做法 |
| --- | --- | --- | --- |
| 一级 | 通常至多处理 1 张牌或 1 次小窗口 | 通常至多值 1 金币，且有条件 | 无条件多摸、无条件跳过对手、永久倍数 |
| 二级 | 通常处理 2 张牌，或改变一轮可见决策 | 约 1--2 金币的期望收益，带条件 | 直接保证本局胜利或无限叠加 |
| 三级 | 可处理 3 张牌，或持续改变一种牌型/资源关系 | 约 2--4 金币的路线价值，风险与收益并存 | 不公开的强制弃牌、永久锁死对手 |
| 四级 | 可以影响一局乃至整桌关键时刻，但必须可数清次数 | 可改变整桌投资节奏，但不能制造无限金币 | 无条件立即胜利、无交互的永久额外回合 |

「处理牌」包括复制、弃置、转化或通过合法出牌额外移出手牌。它不是精确胜率指标；任何让牌数明显超过同级参考的候选，都必须以严格条件、公开信息或明显代价换取。

## 3. 统一装备模型

每个装备在规则快照中至少应记录下列字段。候选阶段可暂用文本，但进入选定列表前必须补齐。

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定、不可复用的英文标识；已上线的 ID 不改语义 |
| `name`、`level`、`category`、`route` | 展示名称、1--4 级、战力/经济、数值/机制/混合 |
| `price` | 常规固定价；升级购买时另记录实际成交价 |
| `effect` | 可由服务端执行的精确效果，含数字、目标与例外 |
| `trigger`、`limit` | 触发窗口、主动/被动、每局或每桌次数 |
| `visibility` | 对手可见、仅持有者可见，及何时公开；已持有的类型与等级默认公开 |
| `state` | 需要持久化的次数、已触发标记、复制牌实例或升级来源 |
| `conflicts` | 与同名系列、同一窗口、突然死亡局的禁用或优先规则 |
| `snapshotVersion` | 随 `landlord-v3` 房间快照冻结的目录版本 |

任何产生手牌的装备必须生成独立实例 ID。复制牌只能参与标准斗地主已有牌型，不能构成五张同点、重复王炸或任何新增牌型；弃掉的实体牌进入公开弃牌区。金币一律以十进制字符串存储、以 `BigInt` 结算。

## 4. 升级系列

允许有明确的四段升级系列，例如「搞一张--搞四张」「小炸弹--超级炸弹」。系列遵守以下规则：

- 高阶装备购买时，若玩家持有其直接前置低阶装备，则成交价为该高阶标价的一半；一级不能半价购买。
- 成交时高阶装备替代前置低阶装备，占用的装备格不变；被替代品不再出售、不再返还金币，也不能与高阶效果叠加。
- 只允许直接相邻升级：持有一级买三级时仍按原价；必须先拥有二级才能半价买三级。
- 高阶在商店出现但没有前置装备时，仍可按原价直接购买。
- 一个系列同一时刻只能持有一个等级。出售高阶后，低阶不会恢复。

这套规则的意义是让早期的廉价选择有后续路线，而不是要求玩家为了升级长期占住多个装备格。每条系列仍须单独评估：四级版本不能只把数字从 3 改成 4，应该在体验上成为真正的变量。同系列相邻等级之间必须改变一个决策点——数量、随机与自选、或触发窗口——只提高数字的候选不算升级。

装备与经济在整桌赛制内跨局保留，到整桌结束才重置；因此半价升级、跨局投资和「整桌一次」的限制都有真实的触发窗口。唯一要避开的是把兑现时点放在整桌结束之后的效果——那时装备和金币都已被清空。

## 5. 触发、公平与兼容

- 商店购买、出售、升级、金币收入、叫抢下注、装备触发均由服务端在房间版本校验下原子提交；客户端只提出意图和所选牌实例。
- 主动效果必须有独立操作窗口和超时默认动作。超时的默认动作应为「不触发」，不得替用户花金币、弃牌或改变目标。
- 对手应能看到已持有的装备类型与等级，以及会影响公开牌局的触发结果；私有商店、未触发的次数和手牌细节不能提前公开。
- 若多个效果在同一窗口触发，先结算出牌本身，再按「本次出牌者的主动选择 -> 本次出牌者被动效果 -> 其他玩家被动效果」处理；选定装备需要写出例外。
- 依赖地主、农民、叫抢地主、赌注、阵营结算的装备，在第 13 局必须明确禁用或给出替代效果。没有定义即默认禁用，不能猜测。
- 新增或修改已选装备时增加目录/规则快照版本，保留旧房间和旧战报的解释。

## 6. 从待定到选定

候选进入选定列表前，至少需要确认：精确文案和术语、触发与超时、公开信息、与八件上限和升级系列的关系、第 13 局行为、与所有现有装备的冲突顺序，以及可测试的正反例。选定不等于立刻实现；实现后还需要服务端规则测试、金币守恒测试和人工正式产物点击验收。
