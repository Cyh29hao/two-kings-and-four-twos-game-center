# 娱乐中心麻将维护约定

## 版本与数据

- `basic-136-v1` / 状态版本 1：保留旧引擎与历史账号积分。
- `basic-136-v2` / 状态版本 2：基础胡牌、独立筹码、无赖子与杠费。
- `ham-v1` / 状态版本 2：旧版 ham 规、人工确认胡牌方案、奖牌和独立筹码；自摸不另加倍。
- `ham-v2` / 状态版本 2：自摸独立 ×2，与杠上开花等独立因素相乘。点炮、抢杠胡不加自摸倍数；保留无赖子 ×2。
- `ham-v3` / 状态版本 2：新房间默认规则；取消无赖子 ×2，保留自摸 ×2、点炮 ×1 与其他牌型倍数。
- 建房保存规则与筹码快照。后续新增规则必须使用新规则 ID，不改写已开桌的快照。
- 胡牌上下文保存本桌 `selfDrawUnit`；旧版选择中的上下文缺失该字段时仍按 ×1。方案、流水、结算与 PNG 使用同一份已确认倍数，历史记录不重新判分。
- 新规则快照及胡牌上下文保存 `noWildBonus: false`；旧快照和已保存的选择上下文缺失该字段时，继续保留无赖子 ×2。不得只删除旧倍数表中的项目。
- 实体牌 ID 为 0–135；语义牌种为 0–33。实体赖子、白板转换、所选赖子代表牌分别保存；不得混用。
- 金额在接口与数据库里为十进制字符串，运算使用 BigInt。规则倍数没有封顶。
- 迁移 0001 追加筹码流水与分享表；0002 追加对局房间索引。无删表、重建账号或转换旧积分操作。

## 模块与提交

`solver.ts` 枚举结构和进牌位置并逐方案判型；不接收牌墙。`modern.ts` 推进牌局、锁定方案后取尾部奖牌、生成筹码流水。`game.ts` 按版本分流。`rooms.ts` 在一次 D1 批次中，以房间版本和随机操作标识保护状态、流水和记录写入。

`win-options` 仅胡牌者可读，完整枚举后分页；服务端重新验证 `candidateId`。正常响应等待 8 秒，有足够信息时提前裁决；选方案等待 60 秒，到期按倍数和固定方案顺序选择，绝不参考牌墙。

记录不可修改。整桌分享保存结束时的摘要与局数上限，再从不可变记录分页读取。公开数据逐字段构造，不直接展开内部状态；分享链接为随机 192 位标识，创建者或管理员可以撤销。PNG 与页面使用相同公开结算对象。

## 回退要求

创建状态版本 2 的房间以后，**不能直接发布本次更新之前的旧版本**。任何紧急回退也必须保留版本分流、ham 引擎、方案接口、账本和追加迁移；可以回退界面样式或暂停开新桌，让已开桌继续完成。不得让旧引擎读取 ham 状态，不得删除新表或重算旧记录。未来不认识的规则/状态必须明确拒绝，不能自动降级到基础玩法。

已创建 `ham-v2` 房间后，回退也必须保留其自摸因子及选择上下文处理；不能用只支持 `ham-v1` 的版本接管。无需新增数据库迁移。

已创建 `ham-v3` 房间后，回退必须继续识别 `ham-v3` 并尊重 `noWildBonus: false`，不能恢复无赖子加倍或把房间降级。

- `tests/mahjong-api.test.ts`、`tests/api.test.ts`：基础麻将、旧积分、斗地主和账号/后台回归。
- `npx tsc --noEmit` 与 `npm run build`。
- 浏览器验证桌面与 390px 手机布局、选择方案、分享、PNG 与后台。测试账号和本地数据库路径仅存在于被忽略的 `work/` 和 `.wrangler/`；不得上传测试数据库、会话或重置令牌。
