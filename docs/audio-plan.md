# 音效扩展计划

这是待实施方案。本轮只修复表情发送，尚未新增这些声音。范围已确认：三款游戏共用表情声音，同时覆盖斗地主牌型和麻将吃碰杠胡。能做出自然、清楚的就加，效果不好的可以保持无声。

## 已经有的声音

站点已有背景音乐、设备普通话播报，以及选牌、出牌、摸牌、通用吃碰提示、炸弹、胜利和倒计时的简单合成音效。入口在 `lib/audio/` 与 `components/table-sound.tsx`。表情已有独立声音开关与音轨字段，当前新表情包没有配音。

## 首轮打算补什么

| 场景 | 声音设计 | 做法 |
|---|---|---|
| 炸弹、王炸 | 短引线声和低沉爆破；王炸加上升声和双重落点 | 改进现有合成效果，避免突兀的大音量 |
| 飞机及带牌 | 短引擎声加掠过声 | 本机合成；三类共享主声，不为挂件重复轰鸣 |
| 顺子、连对、四带二 | 依次翻牌、成对轻敲、主牌与附件两次落点 | 短打击声，与动画关键帧对齐 |
| 春天、反春天 | 明亮的短庆祝旋律 | 原创几音动机，不另播完整歌曲 |
| 吃、碰、杠 | 三次轻碰、三张合拢、四张更厚实的落牌声 | 区分节奏，沿用普通话动作播报 |
| 胡 | 短金色和弦，保留自摸、点炮或抢杠的播报 | 胡牌者确定后一次，选方案及结算不重播 |
| 表情的动作 | 惊讶弹簧声、疑惑滑音、泪滴、庆祝星光、小鸡啾声、猪猪轻哼等 | 先做不依赖演员的卡通拟音，合成不好听的先不加 |
| 人物笑声、哭声、哈欠、口哨、台词 | 配合原动作的真人演绎 | 留给你们录音；没有合适录音就保持无声，不强行用机器语音代替 |

并非所有表情都必须发声。同一种声音可被多个表情引用，但每个表情可以独立调整音量和出现时间。

## 播放规则

1. 延续主动“开启声音”，保留音乐、播报、操作音效和表情声音的独立开关。关闭动画不强制打开声音。
2. 动作音效跟随服务端已确认的公开事件。补杠被抢不播放杠成功，胡牌和结算不会各响一次，不泄露暗杠牌种。
3. 表情先在本机显示；声音在消息确认且仍新鲜时播放一次。接收者按同一个消息编号去重，历史聊天点击重播只作用于本机。
4. 出牌播报与关键倒计时优先，表情音轨最多同时一个；过时或没准备好的声音直接跳过，不排队补播。
5. 切房、切后台和退出时停止声音。音频加载、解码和播放都不能被出牌或发送接口等待。
6. 一次动作只产生一套声音提示。新增公开事件音效后，关闭同一动作旧的日志音效入口，避免双响；暂未迁移的旧房间继续走兼容入口。

## 随内容增加的统一框架

简单短音优先在浏览器本地合成，不产生媒体下载。录音使用一个公共音效目录，固定编号映射到本站音频，登记来源、时长、音量及动画时间点。发送端仍只传表情或事件编号。

需要文件时，扩展现有 `lib/motion/catalog.ts` 的资源类型与统一缓存校验，生成同样带内容指纹的清单；不会给三款游戏另做下载器。当前缓存只支持 WebP，音频接入时必须同时扩展类型校验、体积预算、解码容量和失败降级，不能只把音频路径塞进图片清单。

计划先把短音轨限制为 3 秒、单文件 256 KiB，音频磁盘预算 8 MiB、已解码音频 8 MiB；与现有图片预算共同受总缓存容量约束。准备完成后先用实测调整，再固定到配置。优先暖好小音效和常用表情，后台低并发补齐；新文件只更新变更指纹。缓存满了正常淘汰，缺声音只静音，不妨碍游戏。

你们录音到位后，替换或新增音轨登记并重新生成清单即可；不用修改聊天、游戏引擎和发送按钮。

## 实施顺序与验收

先在图鉴做炸弹、飞机、吃碰杠胡和三类表情拟音的试听样例，再接实际牌桌；不好听的样例不进入首包。需要人工录音的清单单独保留，不卡住可完成部分。

检查三游戏与德州十人桌的连续发送、多人同时动作、冷却重试、抢杠、胡牌方案与开奖阶段、后台恢复、系统静音、手机首次开启声音，以及冷缓存、断网和音频失败。记录点击响应、声音重复次数、下载量和解码占用；持续发声时手牌与操作按钮仍可立即响应。

通过仓库检查、正式构建和实际试听后提 PR；由你合并，再按 [发布流程](releasing.md) 发布 main。
